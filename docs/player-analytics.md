# 玩家分析报表与采集合同

入口 `/d/gameplay-overview`（总览）、`/d/gameplay-players`（玩家一览）。列表链接到 `/d/gameplay-player-detail`，详情导航提供基础数据、游戏日和完整事件。采用 Grafana 原生页面，不创建另一套管理后台。

## 口径

- 总金币为最新余额；零值有效，不累加快照。猫数量只来自明确归属的最新完整快照，包括 UID 0、初始猫和猫舍内猫。缺失不从对话或工具事件推算。
- 时间为北京时间；新增取全局首次登录，昨日及 7/30 个完整自然日不包含今天。时长先按玩家累计去重会话，再计算平均数/中位数。
- 游戏日按玩家、稳定存档 `archive_id` 和 `game_day` 去重。缺存档标识的旧数据不能可靠合并，原始日 metadata 保留会话来源。
- 行为默认历史累计，可切换 Grafana 时间范围。当前状态有独立快照时间。默认包含 Windows/WebGL/unknown；测试数据沿用现有筛选。
- Top 5 按成功操作次数排序，购买另外显示件数；同名商品按稳定商品 ID 分组。做菜同时兼容 `dish_name` 和 `recipe_name`。服装排行按当前穿戴玩家数，不按换装次数。
- 体力新版只累计 `stamina_spent`；旧版业务事件标注旧版样本数，只有同会话/游戏日、相邻序号、相同位置和消耗的开垦双事件才去重。旧版失败钓鱼无法补采。
- 钓鱼记录实际水域、鱼影/普通水域和成功/失败/取消；抛竿数与已观察到结算数并列，未收到结算不能推断为失败。
- 猫升级剩余点数取新奖励之前，另保存奖励后值。工作投入点数与当前工作等级分布分开。
- 当前游戏每玩家一个个人猫舍，升级增加容量。使用率是有有效快照玩家中，从采集开始观察到主动放猫或当前已放猫的比例；未观察到不代表旧版本从未放过。
- 开始输入在首次非空输入时记录；上下文只取最近 60 秒、最多 32 条客户端视口内观察，并独立保存最近台词。明确区分发送与取消，不将模型草稿当作展示。
- 小剧场复用原邀请去重与分类规则，Top 5 默认至少 10 次邀请。Esc 为本地退出，未选择不推断为拒绝。

## 数据与发布

`analytics_event_facts` 是按事件 ID 增量维护的规范事件表，`gameplay_events` / `gameplay_live_events` 保留原始证据。最终会话快照、重传和不同文件的同一事件只计一次；旧事件没有 ID 时使用玩家、会话、游戏日和事件序号组合键。metadata 和 payload 分开保存。迁移标记 `event_facts_v1` 确保旧数据只回填一次。

先备份数据库，停止旧 importer，部署包含新 projection 的 router-api；运行新 importer 的 schema 迁移后核查真实表和视图，再启用新 dashboard。Grafana 配置刷新期间必须避免新查询早于迁移可见。回滚时保留原始表与备份，不删除已新增的原始埋点。

新增 Unity 采集需要客户端和服务器包含同一网络程序集版本；历史缺字段显示“未采集”。本次不修改 CatAgent LLM 请求和 prompt。

## Playtest 批次与 AI 费用

- `playtest_id` 是服务器维护的会话字段。`analytics_playtests` 保存批次起点，`analytics_session_playtests` 以 `(user_id,session_id)` 关联批次；会话和事件 view 暴露同名字段，玩家表显示参与批次。筛选提供全部、中秋playtest、历史／未标记。
- 本次明确从部署后新登录开始，不回填历史。激活时仅执行一次 `INSERT OR IGNORE INTO analytics_playtests VALUES ('中秋playtest', strftime('%Y-%m-%dT%H:%M:%fZ','now'))`。不能在每次服务启动时重设起点。客户端登录时间和服务器接收时间都须不早于起点，已有会话、心跳、退出、旧登录补传不分配新批次；缺登录时间不猜测归属。
- 批次过滤作用于会话、事件及聊天，首次登录仍是全局首次登录，不把老玩家参加新测试计算成新增。原始上传内容保留不改。服务端变更即可生效，无需重新打包游戏。
- 分配只在登录时执行：查找已有会话走 `(user_id,session_id)` 索引，批次配置规模为少数测试轮次，无每帧任务。看板按批次索引过滤，不按导入时间推断历史归属。
- 新版会话 `ai_token_usage.session_estimated_usd` 是多模型调用汇总，优先于旧统一单价计算；逐次调用优先 `estimated_usd`。字段明确为 null 时保留未知，真实 0 保留。旧客户端仍按其上报的单价估算，不套用当前市场价。schema 迁移幂等修复已导入的显式费用，保留原始 JSON。
- 成本是估算而非供应商账单；客户端缓存用量未回报时可为上限。成本表空值显示未采集，混合样本的合计只累计已知金额，不能视为完整账单。

## AI / 小剧场业务面板（2026-09-23）

总览、玩家详情在原有分区之后增加 23 个面板（300–322），保留旧面板位置与费用卡。
新增小剧场发起/开演/完成及演员数、邀请/参与/退出、词汇提交/入库/实际使用、建筑生成/建成/反馈、冒险状态/操作/重复参与、业务调用费用与耗时分布。原问题的“其他”分类占比按明确分类操作计算。

### 采集和统计合同

- `theater_lifecycle`：服务端 offered/completed/cancelled/expired；`theater_line` 实际参与猫 UID 集合含 UID 0。挂载猫数不作为演员数。
- `island_lexicon_result`：created/reused/rejected；`island_lexicon_used` 只来自共享实际使用回调，候选展示不记使用。
- `ai_building_generation`：每次生成一个 flow_id，requested/completed/failed/cancelled，source_id 关联成品。`ai_building_created` 只在首次放置成功保存后记录 building_instance_id；移动和 placed 旧事件不计第二次生成。
- `ai_adventure_state`：存档成功后的状态变更，包含 revision、previous_phase、attempt_id、主题、演员、奖励与关系结果。暂停恢复仍沿用 flow_id。`ai_adventure_action` 为服务器接受的操作。
- `ai_business_request`：统一网关 request_id 与明确 flow_id，完成费用、缺计价、缓存命中、全程/首字节耗时分列。不会与旧 CatAgent 费用卡相加；图片服务未知价格不估价。

场次以 `(archive_id, flow_id)` 去重，多人观看不增加服务端场次。筛选先找相关流程，再通过同一存档/流程索引关联历史结果。已知起点的场次必须起源于所选 Playtest/平台/版本/玩家范围，期间模式以起点进入区间、结果不晚于区间结束为准。旧场次在新 Playtest 恢复不会变成新发起。历史缺发起记录单列，不加入完成率分母。参与意图、本地播放、服务端完成分别展示；Esc 不等于服务端失败。

词汇使用等待和完成历时只计算已观察到可靠起止的样本；冒险暂停独立展示，不宣称历时等于活跃游玩时长。历史生成只展示原始记录次数，无法补采的演员/结果/费用保留未知。生成重试没有旧请求关联时按独立生成流程展示，不猜测重试链。

### 上线与验证边界

先运行 `ensure_schema` 在真实数据库创建 `idx_facts_business_flow` 表达式索引，再刷新 Grafana。客户端代码随下一次游戏发布；看板上线不会让旧包产生新事件。采集覆盖面板用于确认各类新事件实际到达。

Unity 新钩子只在请求、状态转换、词汇操作及实际台词发生时执行，不增加逐帧轮询、地图搜索或事件历史遍历；单次演员处理 O(k)，k 为该场演员数，不调用新的物理/导航 API。现有埋点序列化/上传路径复用；本轮 Editor/离线测试不代表目标 Player/WebGL 性能或线上新游戏流程验收。

`analytics_session_channels` 以 `(user_id, session_id)` 为主键存储客户端明确上报的渠道，覆盖 login/heartbeat/logoff、实时事件批次、历史快照导入。第一个明确值固定本次会话归属，后续未上报不会抹除；不根据历史版本前缀或服务端操作系统补写。
所有共享筛选及详情跳转携带渠道，跨会话业务结果仍按原流程归属统计。上线先创建真实渠道表及索引，再发布依赖此表的查询。
新增渠道数据依赖下一次游戏客户端／服务端发布，旧包及旧记录保留未知。
